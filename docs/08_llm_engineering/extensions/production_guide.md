## E8.1 系统架构设计

### 典型的LLM应用架构

```
用户请求
  ↓
API网关（速率限制、认证）
  ↓
请求队列
  ↓
缓存层（Redis）
  ↓
LLM服务（API或本地）
  ↓
结果缓存
  ↓
用户响应
```

### 关键组件

**1. API网关**
- 认证和授权
- 速率限制
- 请求验证
- 日志记录

**2. 缓存层**
- 查询缓存：缓存相同的查询
- 结果缓存：缓存生成的结果
- 缓存失效策略

**3. 队列系统**
- 异步处理
- 负载均衡
- 优先级管理

**4. 监控系统**
- 性能监控
- 错误追踪
- 成本分析

## E8.2 部署选项对比

### 选项1：完全托管（API）

**提供商：** OpenAI、Anthropic、Google

**优点：**
- 无需维护基础设施
- 自动扩展
- 安全性由提供商保证
- 最新的模型

**缺点：**
- 成本高
- 延迟高（网络往返）
- 数据隐私问题
- 依赖提供商

**成本估算：**
- 小规模应用（1K请求/天）：$30-100/月
- 中等规模（100K请求/天）：$3K-10K/月
- 大规模（1M请求/天）：$30K-100K/月

### 选项2：自部署（云GPU）

**平台：** AWS、Google Cloud、Azure

**优点：**
- 成本可控（长期）
- 低延迟
- 数据隐私
- 完全控制

**缺点：**
- 需要运维经验
- 初期投入大
- 需要管理基础设施

**成本估算：**
- GPU成本：$0.5-2/小时
- 月成本（24/7运行）：$360-1440
- 加上存储、网络等：$500-2000/月

### 选项3：混合方案

**思想：** 结合API和自部署的优势

**架构：**
- 简单任务用便宜的本地模型
- 复杂任务用强大的API模型
- 缓存常见查询

**成本优化：**
- 降低50-80%的成本
- 保持性能
- 灵活应对

## E8.3 监控和告警

### 关键指标

**性能指标：**
- **延迟（P50/P95/P99）**：响应时间分布
- **吞吐量**：每秒处理的请求数
- **错误率**：失败请求的比例

**成本指标：**
- **每请求成本**：平均成本
- **月度成本**：总成本
- **成本趋势**：成本变化

**业务指标：**
- **用户满意度**：用户反馈评分
- **功能完成率**：成功完成任务的比例
- **用户留存率**：用户回访率

### 告警规则

**性能告警：**
```
P95延迟 > 5秒 → 告警
错误率 > 1% → 告警
吞吐量 < 预期 → 告警
```

**成本告警：**
```
日成本 > 预算/30 → 告警
月成本 > 预算 → 严重告警
成本增长 > 20% → 告警
```

**业务告警：**
```
用户满意度 < 3/5 → 告警
功能完成率 < 90% → 告警
```

## E8.4 故障排查

### 常见问题和解决方案

**问题1：延迟高**

原因：
- API响应慢
- 网络延迟
- 缓存未命中

解决方案：
- 检查API提供商状态
- 优化网络连接
- 增加缓存命中率

**问题2：成本高**

原因：
- 请求量大
- 使用了贵的模型
- 缓存效率低

解决方案：
- 使用便宜的模型
- 优化提示长度
- 改进缓存策略

**问题3：错误率高**

原因：
- 模型返回错误
- 输入验证失败
- 速率限制

解决方案：
- 改进输入验证
- 实现重试机制
- 增加速率限制

## E8.6 性能优化

### 缓存策略

**查询缓存：**
```python
cache_key = hash(prompt)
if cache_key in cache:
    return cache[cache_key]
else:
    result = llm.generate(prompt)
    cache[cache_key] = result
    return result
```

**缓存失效：**
- TTL（时间失效）
- LRU（最近最少使用）
- 手动失效

### 批处理

**优势：**
- 减少API调用次数
- 提高吞吐量
- 降低成本

**实现：**
```python
def batch_generate(prompts, batch_size=10):
    results = []
    for i in range(0, len(prompts), batch_size):
        batch = prompts[i:i+batch_size]
        batch_results = llm.generate_batch(batch)
        results.extend(batch_results)
    return results
```

### 模型选择

**性能 vs 成本权衡：**
- 简单任务：用小模型
- 复杂任务：用大模型
- 混合方案：根据任务难度选择
